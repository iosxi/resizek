# resizek

写真を「共有」するだけで、**いつもの大きさに縮めてクリップボードへ**載せる Android アプリ。
LINE などで写真を送るとき、受け取る相手のデータ通信量（いわゆるギガ）を減らすためのもの。

- 対応: Android 9 (API 28) 〜 最新 (targetSdk 36 / Android 16)
- 出来上がり: `resizek.apk` — **約 25 KB**
- 要求する権限: **無し**

> **実機で確認済み。** AQUOS SH-M16 (Android 12) と Xperia XQ-FS44 (Android 16) で、
> Google フォトから共有 → 縮小 → コピー → 別のアプリ (Chrome) へ貼り付け、まで通している。
> 測った値は下の「実測」に載せた。**LINE への貼り付けそのものは確かめていない**
> （誤って誰かに送らないよう、検証は Chrome で行った）。

## 使いかた

1. 写真アプリ（Google フォト、カメラのギャラリーなど）で写真を開き、**「共有」→「resizek」**。
2. 長いほうの辺が設定の大きさ（はじめは **800 px**）になるまで縮めた写真が出る。
   4000 × 3000 の写真なら 800 × 600、縦の写真なら 600 × 800。
   下に「800 × 600 · 105 KB / 元 4000 × 3000 · 3.0 MB（約 1/29 に）」のように大きさが出る。
3. **「コピー」**を押す。
4. LINE などに移って、入力欄を長押し →「貼り付け」。

コピーした後に他のアプリへ移ると、resizek の画面は自分で閉じる
（共有元の写真アプリに戻ったとき、上に重なって残らないように）。
クリップボードの中身は閉じても消えない。

## いつもの設定

アプリ一覧の resizek を開くと、設定の画面になる。あるのは二つだけ。

| 設定 | 選べる値 | はじめ |
| --- | --- | --- |
| 長辺の大きさ | 480 / 640 / 800 / 1024 / 1280 / 1600 / 1920 px | 800 px |
| 画質 (JPEG) | 60 / 70 / 80 / 90 | 80 |

元から設定より小さい写真は、大きさはそのままで JPEG に書き直す
（「元から小さいので大きさはそのまま」と出る）。

## 縮めた写真に入らないもの

- **位置情報・機種名などの撮影データ (EXIF)。** JPEG を新しく書くので引き継がれない。
  貼り付けた先で受け取ったファイルを調べ、EXIF の入る APP1 が無いことを確認した。
- **Ultra HDR の明るさの地図 (gainmap)。** Android 14 以降で付いている写真は、
  そのまま書くと JPEG に同梱されて重くなるので落とす（実機での確認はしていない。下の「未確認」）。

向き (EXIF の回転指定) は直してから縮めるので、縦で撮った写真も縦のまま出る。
広色域 (Display P3) の写真は sRGB に揃える（色の情報を読まない受け手でも色が転ばないように）。
透過のある PNG は、透けた所を白で埋める。

## 入れかた

`resizek.apk` を端末に移して開き、インストールする（提供元不明のアプリの許可が要る）。
adb が使えるなら:

```
adb install -r resizek.apk
```

## 権限について

要求している権限は無い。

| ふつう要りそうな権限 | resizek がそれを避けた方法 |
| --- | --- |
| ストレージの読み取り | 共有元が共有のときに付けてくれる、その 1 枚だけの一時的な読み取り許可で読む |
| ストレージの書き込み | 縮めた写真はアプリ自身の領域 (`files/out/`) に置く |
| `INTERNET` | 通信しない |

縮めた写真は、自前の小さな `ContentProvider`（`OutProvider`）から `content://io.resizek.out/…`
として渡す。**外には公開していない** (`exported=false`)。読めるのはクリップボードから
貼り付けた相手だけで、その瞬間にクリップボードが一時的な読み取り許可を付ける。
出来上がりは新しいほうから 10 枚だけ残し、古いものは消す
（キーボードのクリップボード履歴から少し前のものを貼っても切れないように）。

### 貼り付けられなくなる場合

resizek を設定から**「強制停止」すると、それまでに貼り付けた相手への読み取り許可を
Android が取り消す**。そのため「一度貼り付けた画像を、強制停止の後にもう一度貼り付ける」と
読めない。もう一度共有し直せばよい。
メモリ不足でアプリが裏で終了した場合や、コピー直後に強制停止して**初めて**貼り付ける場合は
問題なく貼れる（どちらも確認済み。貼り付けの瞬間に resizek が起こされる）。

## 作りかた

Gradle を使う道と、使わない道の両方が置いてある。
**どちらも同じ鍵で署名した同じアプリを作る**ので、互いに上書き更新できる
（証明書の SHA-256 が一致することを確認済み）。

### Gradle 無し（速い。Android Studio が要らない）

```
bash tools/build.sh
```

Android SDK の道具（aapt2 / javac / R8 / zipalign / apksigner）だけで組み立てる。
版 (versionCode / versionName) は `app/build.gradle` から読む。
`keystore/resizek.jks` が無ければ最初の一回で自動的に作る。
出来上がりは `build/resizek.apk`、ついでにルートにも `resizek.apk` として置く。

### Gradle

```
./gradlew assembleRelease
```

出来上がりは `app/build/outputs/apk/release/app-release.apk`（約 30 KB。
AGP が dex を無圧縮で入れるぶん嵩む）。

### 署名鍵

`keystore/resizek.jks` と `keystore.properties`。
**この二つはリポジトリに入れていない**（入れると誰でも resizek を名乗る APK に署名できてしまうため）。
配布する版を作った鍵は**無くさないこと。** 鍵が変わると、端末は別のアプリとみなして
上書きインストールを拒む。

## 中身の作り

外部ライブラリは使っていない（AndroidX も無し）。これが 25 KB の理由。

| ファイル | 役目 |
| --- | --- |
| `ShareActivity.java` | 共有から開く画面。縮小を裏で走らせ、出来上がりを見せてコピーする |
| `Shrinker.java` | 写真を読んで縮め、JPEG に書く |
| `OutProvider.java` | 縮めた写真を他のアプリへ渡す口（AndroidX の FileProvider の代わり） |
| `SettingsActivity.java` | アプリ一覧から開く画面。使い方と、長辺・画質の設定 |
| `Prefs.java` / `Ui.java` | 設定の読み書き / 画面を組む小道具 |

- **`ImageDecoder` (API 28〜) で読む。** EXIF の向きを自分で直し、HEIF も読める。
  `setTargetSize` は復号の段階で間引くので、大きな写真でも全画素を展開しない。
- **見せるのは書き出した JPEG そのもの。** 縮める前の絵ではなく、相手に届くのと同じ絵
  （画質の粗さも含めて）を画面に出す。
- **縮小は主スレッドの外で。** 画面はすぐ出て、出来上がりを待つ間はくるくるが回る。
- **回転で作り直さない。** 構成の変化は自分で受け、縮小をやり直さない。
- **レイアウト XML を使わない。** 画面は Java で組む。
- Android 15 以降の全画面描画の強制に合わせ、どの版でもシステムバーの分の余白は自分で取る。

## 実測

### 大きさ

| 測ったこと | 結果 |
| --- | --- |
| APK (`tools/build.sh`) | **25,230 bytes** |
| APK (Gradle) | 30,732 bytes |
| `classes.dex` | 20,428 bytes |
| 宣言している権限 | 無し（`aapt2 dump badging` で確認） |

### 縮小の結果（設定は長辺 800 px・画質 80、ただし 1 行目は 1280 px）

すべて Google フォトから実際に共有したもの。時間は読み込みから JPEG を書き終えるまで。

| 端末 | 元 | 出来上がり | 時間 |
| --- | --- | --- | --- |
| SH-M16 | 4000 × 3000 JPEG · 3.1 MB（設定 1280 px） | 1280 × 960 · 146 KB | 272 ms |
| SH-M16 | 4000 × 3000 JPEG、90° 回転指定 · 3.3 MB | **600 × 800** · 97 KB（約 1/35） | 262 ms |
| SH-M16 | スクリーンショット PNG 1080 × 2400 · 104 KB | 360 × 800 · 18 KB | 110 ms |
| SH-M16 | PNG 512 × 512 · 149 KB（縮小不要） | 512 × 512 · 114 KB | 84 ms |
| XQ-FS44 | 4000 × 3000 JPEG、90° 回転指定 · 2.2 MB | **600 × 800** · 74 KB（約 1/31） | 78 ms |
| XQ-FS44 | 4000 × 3000 JPEG · 3.0 MB | 800 × 600 · 105 KB（約 1/29） | 68 ms |

### 起動

冷えた状態からの起動（XQ-FS44、`am start -W -S` の TotalTime、10 回ずつ）。

| 画面 | 中央値 | 最小〜最大 |
| --- | --- | --- |
| 共有から開く画面 | 85 ms | 74〜103 ms |
| 設定の画面 | 78 ms | 71〜83 ms |

### 貼り付け

PC に置いた検証用のページを端末の Chrome で開き、入力欄を長押し →「貼り付け」して、
ページが受け取ったファイルを DevTools から読んだ。

| 確かめたこと | 結果 |
| --- | --- |
| SH-M16 (Android 12) で貼り付け | `image/jpeg`・99,368 bytes・600 × 800 — 書き出したファイルと同じ |
| XQ-FS44 (Android 16) で貼り付け | `image/jpeg`・76,285 bytes・600 × 800 — 同上 |
| コピー後、resizek をメモリ不足相当で終了させてから貼り付け | 貼れた（`Start proc … for content provider` で起こされる） |
| コピー直後に強制停止し、初めて貼り付け | 貼れた |
| 一度貼った後に強制停止し、同じ相手が貼り直し | **読めない**（`Permission Denial`。上の「貼り付けられなくなる場合」） |
| 貼り付けた JPEG の EXIF | 無し（マーカーは JFIF・ICC・量子化表…のみ。EXIF 付きの対照では検出できることを確認） |
| コピー後に他のアプリへ移ったとき | resizek の画面は閉じる（アクティビティが残っていないことを確認） |
| Android 16 の全画面描画 | 写真・文字・ボタンがシステムバーに潜らない |

### 未確認

- **LINE への貼り付け。** 上のとおり Chrome では確かめたが、LINE そのものでは試していない。
- Android 9〜11 の実機。`minSdk 28` で組んであり、API 30 以降の呼び出しは分岐で避けてある。
- HEIF の写真と Ultra HDR の写真（手元の 2 台のカメラはどちらも出さない）。
- 透過のある PNG の白埋め（手元に透過 PNG が無かった）。
